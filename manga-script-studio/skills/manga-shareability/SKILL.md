# Shareability strategy

Read the source pages and specify the likely sender, recipient and occasion. “A former stagehand sending this to a castmate” suggests a more testable reason to share than “everyone likes underdogs.” Give newcomers an entry without requiring fandom knowledge.

1. Locate an image, exchange or short sequence that delivers a small pleasure by itself and leaves a genuine open question. State the exact panel boundary where promotion must stop. Check surrounding images, captions, thumbnails, filenames and alt text for spoilers.
2. Draft the requested cut and copy. For a comparison or discovery campaign, offer two honest variants drawing on different reasons to pass the story along, such as recognition and curiosity. Anchor every promise in the pages. Attribute the work as instructed, leave lettering legible at intended size, and write alt text describing only the selected visual.
3. Separate a public teaser from a jury synopsis, which may require the ending. If a contest or rights restriction matters, [check it](../manga-contest-readiness/SKILL.md) before scheduling a release. An unresolved rule permits private drafting. Publishing, posting and contacting readers are separate actions.
4. When testing is requested, compare versions with a single changed variable. Set one primary signal with a defined numerator, denominator, audience, window and counting unit. Pair it with a guardrail such as spoiler complaints or whether starters reach the promised scene. For tiny samples, report counts and treat reactions as directional. If metrics are unavailable, ask what a cold reader would tell a friend and which image prompted it.

**Deliver** the requested preview with source IDs, its spoiler boundary and the requested accessibility copy. For a discovery strategy, include the reason to share and a private test card with a decision rule. A single private excerpt needs only its requested materials. Use the [discovery worksheet](../../templates/discovery-test.md) and [discovery rubric](../../rubrics/reader-discovery.md) when planning tests. Keep predicted behavior separate from measured results.
