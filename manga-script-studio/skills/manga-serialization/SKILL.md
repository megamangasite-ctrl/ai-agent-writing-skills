# Serialization and retention

Name the pleasure a reader can expect again and the state that changes permanently each time. Bring the intended length, release rhythm if known, cast and production limits. Let a sustainable engine generate different problems without undoing earlier growth.

1. Write one episode-sized question and settle it in the pilot. Let the resolution create a second question through a decision, debt, new alliance, altered rule, or changed role. A quiet appointment can earn a return just as a danger can.
2. Generate two further episodes by varying who wants what or which rule is strained. Raise the cost or intimacy when appropriate. If all three depend on withholding the same answer, pay that debt earlier and find a new consequence.
3. Maintain a short ledger of promise, plant, partial answer, due chapter, settlement and surviving change. Keep an inventory of who knows what, and flag obligations that would overwhelm the next chapter's page budget. Mark projected settlements as planned.
4. For a returning reader, provide one image or action that restores necessary context while advancing the new scene. For a newcomer, identify the local goal they can understand unaided. Compare the opening and closing state of each chapter for a meaningful difference.
5. If actual reader data exists, note where the loss occurs and list competing explanations, including release timing or unclear staging. Use comparable cohorts before attributing a change to the writing. With no data, present a retention hypothesis and a cold-read test.

**Deliver** the pilot's local close, the resulting return question, a brief run of differentiated chapters, and the [series ledger](../../templates/series-ledger.md). Keep future story material proportional to the requested horizon.
